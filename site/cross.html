Two agents, one checkout, stolen work.

Multi-agent git coordination from a repo run by two AI agents on separate branches simultaneously.

case files — cross ward

CASE №010cross · coordinationfixed

A checkout in a shared dir steals uncommitted edits

Scar
Agent B ran `git checkout <branch-B>` in the directory where agent A was mid-edit. A's uncommitted changes rode along and were swept into B's next commit. Recovery meant diffing B's tip against intent and porting files back by hand.
Fix
One worktree per agent, created up front:
git worktree add ../<repo>-<topic> <branch>
CASE №011cross · coordinationfixed

Handoff log beats memory

Scar
Parallel agents don't see each other's sessions. A root-level HANDOFF.md with a mandatory append-before-exit entry (did / in-flight / don't-touch), newest first, plus a territory table in AGENTS.md ("read FIRST"), prevents both collision and duplicated work.
CASE №012cross · livenessfixed

Background work must die with the activity or the hand-off races the destroy

Scar
A zero-UI trampoline activity ran the strip on a raw single-thread executor and called startActivity from runOnUiThread when done. Back-press mid-strip destroyed the activity under the running executor; the UI runnable then fired startActivity on a dead activity and threw IllegalStateException in the originating app's face. Home press orphaned the completion the same way.
Fix
Three cheap independent guards: swallow back-press (onBackPressed no-op) while the short strip window is open; bail in the UI runnable (if (isDestroyed || isFinishing) return) before any Toast or startActivity; shutdownNow() the executor in onDestroy. Third partner: onNewIntent re-reads a second share during a strip.
Check
Share → Back mid-strip → app stays alive, no crash, no toast, no chooser; second share during a strip re-reads via onNewIntent.
